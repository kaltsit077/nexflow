# Game Runner 使用说明

Game Runner 是桌面端**调度器**：预先配好路径与队列后，**点一次「运行选中队列」即应跑通全流程**（含先拉起模拟器/游戏/助手），不必再手动开游戏。

- **自有识图脚本** → 官方 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 项目（`type=maafw`，用 `MaaPiCli -d` 跑）
- **别人做好的助手** → 当黑盒启动（MAA.exe、BetterGI、三月七助手等）；多步链路用队列前序 `wait_mode=launch`
- **不是**网页壳；**也不负责**写游戏内部逻辑（识图流程在 MaaFW 里写）
- **运行形态** → 与明日方舟 MAA 一样，以**整个文件夹**为准；日常用源码目录 + `start.bat`。功能做完前**不优先打包**单文件 exe。

```text
[PySide6 界面 / CLI]
        ↓
[runner 执行器]  顺序 · 超时 · 重试 · 失败策略 · 杀进程树
        ↓
  maafw → MaaPiCli -d    |    exe / python / bat → 外部工具
```

## 1. 环境准备

### 1.1 依赖

- Windows 10/11
- Python 3.9+（已加入 PATH）
- 本仓库路径示例：`E:\AAAmobile game\game-runner`

```bat
cd /d "E:\AAAmobile game\game-runner"
pip install -r requirements.txt
```

含 `MaaFw==5.14.2`（进程内录制 / 连控）。

### 1.2 安装 MaaFramework 运行时（跑自有脚本 + 编辑里录制必做）

```bat
tools\setup_maafw.bat
```

默认下载官方 **v5.14.2** win-x64 到 `maafw\`（与 pip `MaaFw` 对齐）。也可：

```bat
tools\setup_maafw.bat "D:\path\to\maafw_bin"
```

成功后应有：`maafw\MaaPiCli.exe` + `MaaFramework.dll`。  
环境变量 `GAME_RUNNER_MAAFW` 可覆盖目录。

> 注意：BD2 目录里较旧的 `maafw` 只适合给该项目的 `MaaPiCli -d`（脚本项里的 `maafw_bin`）；**不要**拿旧 DLL 喂给当前 Python 绑定。

### 1.3 安装 OCR 模型（要用文字识别时）

```bat
tools\setup_ocr.bat
REM 指定项目：
tools\setup_ocr.bat "projects\click_lab"
```

会把 `det.onnx` / `rec.onnx` / `keys.txt` 拷到  
`projects\<项目>\resource\model\ocr\`。

### 1.4 启动（日常只用这个）

| 方式 | 命令 |
|---|---|
| 桌面 UI | `start.bat` 或 `python main.py` |
| 命令行 | 见第 6 节 |

在仓库根目录运行，保证同级有 `maafw\`、`projects\`、`config.json`。  
出错日志：`logs\start_errors.log`。

> 不要用旧的 `dist\GameRunner.exe` 当日常入口（易缺旁边的 `maafw\`）。打包延后，见第 7 节。

## 2. 界面（链路 = 分区）

固定间距 12px。三条链路分三块（详见 [`功能接口与布局.md`](功能接口与布局.md)）：

| 区 | 做什么 |
|---|---|
| **顶栏 获取** | 导入 · 游戏目录 · 历史 |
| **中栏 编排** | 左队列（折叠/目标/步骤）· 右脚本库（加入/拖拽/编辑） |
| **底栏 执行** | 日志 · **唯一**「运行选中队列」· 停止 |

步骤上的「跑」只测单脚本；整队只从底栏跑。  
改脚本路径 / 录制：脚本库 **编辑**（一窗含「录制/连控」）。步骤 **队列参数** 只调失败重试等。

### 2.0 游戏目录（全部项目 / 一键安装）

顶栏 **游戏目录**：浏览已知助手，从官方 GitHub Release **安装到本地统一目录**（类似 mod 管理器），并尽量自动登记到脚本库。

**目录约定（路径用英文 `library`，避免部分助手不支持中文路径）：**

```text
library/                         ← 全部项目
  README.txt
  maa_arknights/                 ← 分项目（按助手 id）
    app/                         ← 项目本体（下载解压的程序）
    scripts/                     ← 项目脚本（说明、bat、自写补充）
    meta.json                    ← 安装记录
  bettergi/
    app/
    scripts/
    …
```

| 操作 | 说明 |
|---|---|
| 安装 / 更新 | 下载到 `library\<id>\app\`，能识别则写入 `config.json` |
| 扫描全部项目并导入 | 优先 `app\`，也会试分项目根目录及一层解压子目录（兼容手动乱放） |
| 打开文件夹 | 打开 `library\` |
| 仅有主页的项（如 LCBA） | 浏览器下载后，把本体放进对应 `app\`，再扫描或「导入」 |

已收录示例：明日方舟 MAA、原神 BetterGI、星铁三月七、鸣潮 ok-ww、碧蓝 Alas、棕色尘埃 MFABD2、代号鸢 MaaYuan、NIKKE MaaNikke、MXU、MaaFW 运行时、click_lab；LCBA/KAA 为说明+手动。

国内 GitHub 慢：`set GAME_RUNNER_GH_PROXY=https://ghproxy.net` 后重启再装。`.7z` 需本机 [7-Zip](https://www.7-zip.org/)。安装型 `.exe` 会启动向导，装完再扫描。

**API 限流：** 游戏目录底栏 **GitHub Token…** → 浏览器创建 Token → 粘贴保存（写入本机 `.github_token`，已 gitignore）。也可设环境变量 `GAME_RUNNER_GITHUB_TOKEN` / `GITHUB_TOKEN`。

### 2.1 编排 → 执行

1. 中栏左 `+ 队列`；点标题设目标（绿框）；▶/▼ / 全开全收 / 改名；队列可选 **顺序 / 并行**（并行默认最多 2 路）  
2. 中栏右：筛选 → **加入**（当前目标队列）/ **拖进队列**；**目录**打开工作目录，**启动**单跑该脚本  
3. 步骤 ▲▼ 调序；**编辑**（同脚本库一窗，含录制）；脚本 ① 可填 **lane**（如 `emulator` / `pc`，同名互斥）；**队列参数**（重试/失败策略）；单步 **跑** 仅试跑  
4. 底栏 **运行选中队列** / **停止**；看同区日志  

**并行示例**：游戏 A（模拟器）`lane=emulator` + 游戏 B（PC）`lane=pc` 可同开；其后同 `emulator` 的 C 等 A 结束再开，且全局不超过 `max_parallel`（默认 2）。占槽：`wait_exit` / `launch_wait` 等到进程退出；`launch` 在 settle 后释放。  

**串行全流程（场景 1）**：模拟器步用 `launch`；助手步用 **`launch_wait`**（settle → 代点开始 → 等助手退出）+ **`cleanup=self`**（或 `self+pre` 连前置一起关）；下一游戏再下一步。  


5. 游戏目录里每项也可点 **目录** 打开 `library\<id>\app`  

示例：Alas 行点「目录」进 `AzurLaneAutoScript`；或「启动」直接开助手；编排进队列则用底栏跑。

### 2.2 脚本编辑 / 导入（含录制）

右侧脚本行 **编辑**：一个窗口配齐——页签 **① 基本与调度** + **② 录制/连控（maafw）**。  
右侧 **管理…** / **+ 新建**：左侧脚本列表 + 同一编辑器。  
顶栏 **导入**：选文件夹/文件 → **识别** → **导入并保存**（会出现在右侧脚本库）。

支持探测示例：

| 路径里有什么 | 导入类型 | 调度友好参数 |
|---|---|---|
| `interface.json`（MaaFW PI） | `maafw` | 默认 `MaaPiCli -d`（需先交互配好 `maa_pi_config.json`） |
| `MAA.exe` + `MaaCore.dll` | `exe`（明日方舟 MAA） | 启动 GUI；日程也可在 MAA 内配 |
| `BetterGI.exe` | `exe` | 启动 GUI |
| `March7thAssistant.exe` 等 | `exe` | 启动 GUI |
| `ok-ww.exe`（鸣潮） | `exe` | 默认 `-t 1 -e`（跑启动页第 N 个任务后退出） |
| `Start.exe` + `_internal`（LCBA） | `exe` | 仅 GUI；靠 `LCBA_config.txt` |
| `Alas.exe` + `alas.py` | `exe` | 启动 GUI；日程在 Alas 内 |

**脚本字段：**

| 字段 | 说明 |
|---|---|
| ID | 唯一标识，队列步骤用它引用 |
| 类型 | `maafw` / `exe` / `python` / `bat` / `cmd` / `powershell` / `ahk` |
| 路径 | `maafw` = 含 `interface.json` 的目录；其它 = 可执行文件或脚本 |
| 工作目录 | 可选；`exe` 类常设为工具目录 |
| 参数 | 逗号分隔；`maafw` 常用 `-d` |
| maafw_bin | 可选；该脚本专用的 `MaaPiCli` 目录（如 BD2 自带 `maafw`） |
| 超时(秒) | 超时后杀进程树 |
| 前置启动 `pre_launch` | 可选；先拉起模拟器/游戏再跑本脚本 |
| 启动后点击 `after_launch` | 可选；助手窗口出现后代点坐标。配合 `launch` 或 `launch_wait` |
| 收尾 `cleanup` | `none` / `self` / `self+pre`；默认 `self`；仅成功且非纯 `launch` 时杀进程 |
| 管理员启动 | Windows 默认：`start.bat` 自提权；`type=exe` / 前置启动 / 录控「启动并连接」用 UAC `runas`（MAA PC 端需要）。脚本可写 `"run_as_admin": false` 关闭 |
| 标签 | 方便筛选，逗号分隔 |

**MAA 一点龙（示例）：**  
1. ① 等待模式 = `launch_wait`（要等日常跑完）或 `launch`（只拉起）；可选前置 = 模拟器；收尾选 `self` / `self+pre`  
2. 先手动开一次 MAA → 编辑 → ② 助手连控 → 连接 → 实时截图 → 勾选「录制中」依次点需要的按钮 → 左侧可改坐标/延迟 → **写入配置**（多步在同一脚本内；队列留给多脚本编排）  
3. 库「启动」或队列运行 → 自动开 MAA 并点击  

示例：Alas 也可同样：前置 MuMu + 启动后点 Alas 开始（若需要）。

步骤弹窗字段：`script` / `on_fail`（stop|continue）/ `retry` / `preset` / `fallback`。

### 2.3 录制 / 连控（在「编辑脚本」里）

**不再有顶栏「工作室」**。对 `type=maafw` 的脚本点 **编辑** → 切到 **② 录制/连控**，即加载该脚本路径下的 PI 项目。

走与 MXU **同一套** 官方 API：`Toolkit` 枚举设备 → `Win32Controller` / `AdbController` 连接 → `post_screencap`；可试跑任务、叠加识别框、录制导出。

**一次准备（版本必须对齐）：**

```bat
pip install -r requirements.txt
tools\setup_maafw.bat
```

`maafw\` 需为 **v5.14.2** 官方 bin（与 `MaaFw==5.14.2` 一致）。旧版 BD2 自带 DLL 不能给进程内连控用。

**② 布局（与助手对齐）：** 上=连接条（窗口/过滤/连接，maafw 另有 PI 项目；截图方式在「高级」）· 下左=步骤 · 下右=实时截图（占满剩余）· 底=日志可折。不把 ② 再套一层滚动，避免截图被挤出屏幕。

**操作：**

1. 脚本库对该 maafw 脚本点 **编辑**，① 确认路径并 **保存脚本**  
2. 切到 **②**（按路径自动加载 PI）  
3. 上方选窗口 → **连接** → **▶ 实时截图**（截图方式等在「高级」）  
4. 下左勾选 **录制中**（默认 **模板裁切**；坐标为备选）→ 在右侧画面依次点  
5. 左侧可改名/坐标/▲▼/删；**用上次点击覆盖** 时模板步会按当前帧重裁  
6. 可 **+等待** / **OR 候选** → 填任务名 → **导出到项目** → 对话框可 **试跑刚导出的任务**  

「启动程序」会随脚本保存（`studio_launch`），只方便录控，**不**代替队列里的 `type=exe`。

导出写入 `resource/pipeline/recorded_*.json`、`resource/image/`，并登记 `interface.json`。  
复杂分支用 [MaaPipelineEditor](https://mpe.codax.site/stable/) / MXU 精修；Game Runner 只做稳定草稿。

无人值守调度仍用主台 **开始任务** → `MaaPiCli -d`（可继续指向 BD2 自己的 `maafw_bin`）。

| 能力 | Game Runner 编辑·录制页 | MXU |
|---|---|---|
| 官方控制器截图（FramePool 等） | 有 | 有 |
| 试跑任务 + 识别框 | 有 | 有 |
| 多配置页 / 定时 / 更新器 | 弱（调度器侧用队列） | 强 |
| 多工具串联调度 | 有 | 无 |

顶栏 **历史**：历次运行的时间、结果、退出码、耗时、错误摘要。点 **刷新** 更新。

## 3. 脚本类型怎么配

### 3.1 `maafw`（自有识图自动化）

```json
{
  "id": "click_lab",
  "name": "识图点按实验",
  "type": "maafw",
  "path": "projects/click_lab",
  "args": ["-d"],
  "timeout_sec": 600
}
```

- `path`：PI 项目根目录（必须有 `interface.json`）
- 执行：在该目录下跑 `MaaPiCli.exe -d`
- 首次建议在项目目录**交互跑通一次**，生成 `config/maa_pi_config.json`，再无人值守 `-d`

BD2 若自带运行时，可设：

```json
"maafw_bin": "E:/AAAmobile game/BD2MAA/maafw"
```

### 3.2 `exe`（外部助手）

指向已安装好的工具 exe，工作目录设为工具根目录。调度器只负责启动；任务内容在工具自己的界面里预先配好。

### 3.3 `python` / `bat` / 等

本机可执行即可。源码运行时 `type=python` 用当前解释器；若以后做目录版发布，目标机仍需自备 Python（或改成 `exe`/`bat`）。

## 4. 自有脚本：识图点按（预制流程）

详细练手见 [`projects/click_lab/DEV.md`](../projects/click_lab/DEV.md)。这里是总览。

### 4.1 一次装好 + 打开实验项目

```bat
tools\setup_maafw.bat
tools\setup_ocr.bat
tools\open_click_lab.bat
```

### 4.2 基本公式

每个节点 = **识别** +（可选）**动作** + **下一步**

```json
"节点名": {
  "recognition": {
    "type": "OCR",
    "param": {
      "expected": "确认",
      "threshold": 0.5,
      "roi": [左, 上, 宽, 高]
    }
  },
  "action": { "type": "Click" },
  "post_delay": 500,
  "next": ["下一个节点"]
}
```

| 识别 | 用途 |
|---|---|
| `TemplateMatch` | 比对 `resource/image/` 里的按钮小图 |
| `OCR` | 认屏幕文字（需 OCR 模型） |

| 动作 | 用途 |
|---|---|
| `Click` | 点识别框中心（也可固定坐标） |
| `Swipe` / `Key` / `DoNothing` | 见官方 Pipeline 文档 |

- `roi: [0,0,0,0]` = 全屏；正式用请缩小 ROI  
- 素材按 **短边 720** 缩放后的画面裁切（与 BD2 / 官方一致）  
- 模板用**无损 PNG**

### 4.3 预制时如何截图（没有「录宏」）

Game Runner **不内置录键鼠**。预制靠 Maa 生态截图裁切：

1. 用 Cursor / VS Code 打开 `projects/click_lab`（或你的游戏资源目录）
2. 安装插件：**Maa Pipeline Support**（`nekosu.maa-support`）
3. 命令面板 → `Maa: 打开截图工具`
4. 连接控制器（Win32 窗口 / ADB）→ **截图**
5. **Ctrl + 拖框** 裁按钮 → **下载** 到 `resource/image/`
6. 需要时 **复制** ROI 数组，贴进 pipeline 的 `roi`
7. 写好节点后，用 MXU 或 `MaaPiCli` 试跑

可选工具：

| 工具 | 用途 |
|---|---|
| [MXU](https://github.com/MistEO/MXU) | 连窗、截图、跑任务、看识别框 |
| [MaaPipelineEditor](https://mpe.codax.site/stable/) | 可视化编 pipeline |
| VS Code `nekosu.maa-support` | 截图裁切、任务跳转、试跑 |

### 4.4 click_lab 三个示例任务

| 任务 | 作用 |
|---|---|
| OCR点确认 | 窗口出现「确认」则点击（可用记事本练习） |
| 模板点按钮 | 匹配 `resource/image/my_button.png` 后点击 |
| 组合流程示例 | `next` / `JumpBack` 分支演示 |

记事本练习：打开记事本，输入 `确认` → 控制器选「记事本练习」→ 跑 OCR 任务。

### 4.5 换成真实游戏

1. 复制 `projects/click_lab` → `projects/我的游戏`
2. 改 `interface.json` 的 `window_regex`（或改用 ADB）
3. 换自己的 pipeline / 图片；需要 OCR 时再跑一次 `setup_ocr.bat "projects\我的游戏"`
4. 在「脚本 / 导入」里导入该目录（`type=maafw`）
5. 交互跑通一次生成 `config/maa_pi_config.json`，再加入任务列表用 `-d` 调度

### 4.6 识图能做到什么 / 做不到什么

**适合：** 日常导航、点固定按钮、关弹窗、循环刷本、判断是否在某界面。

**不适合当唯一手段：** 精确读伤害数字、强特效遮挡、频繁换皮 UI、需要局内最优解算的玩法（那是另一类方案，不在本调度器范围内）。

## 7. 清理与（延后的）打包

### 7.1 日常：源码整目录

与 MAA 相同思路——**整夹一起用**，入口是小启动脚本，不是巨型单文件：

```bat
start.bat                 REM 推荐入口（缺依赖/maafw 会尝试补齐）
python tools\doctor.py    REM 环境自检
python tools\disk_usage.py
clean.bat                 REM 清 build/logs/.cache 解压残留、旧 dist 打包垃圾
clean.bat --deep          REM 再删 .cache 里的 zip
```

- `setup_maafw.bat` 成功后会删掉 `.cache` 全量解压，只留 zip  
- 运行日志启动时自动修剪；关闭「编辑脚本」会停预览并断开控制器  

### 7.2 打包：功能做完再说

```bat
build.bat                 REM 仅提示：请用 start.bat（不打包）
build.bat --force         REM 临时目录版 → dist\GameRunner\（onedir，非整包单文件）
```

以后正式分发时约定：

1. 发布 **整个 `dist\GameRunner\` 文件夹**（或直接发源码目录），不要只拷一个 exe  
2. `maafw\` 与入口 exe / 仓库根同级  
3. OCR 模型另跑 `tools\setup_ocr.bat`，不塞进发布包

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 环境不齐 / 不知缺啥 | `python tools\doctor.py` |
| 找不到 `MaaPiCli.exe` | 从**仓库根**跑 `start.bat`（会检查/安装 `maafw\`），或手动 `tools\setup_maafw.bat` |
| 编辑→录制页「设备/窗口」是空的 | 同上；确认不是旧的 `dist\*.exe`；点「刷新」；过滤框先清空 |
| OCR 无结果 | 跑 `tools\setup_ocr.bat`；检查 `resource/model/ocr/` |
| 模板总对不上 | 用插件按 720 短边规则截图；收紧 `roi`；略降 `threshold` |
| `-d` 立刻退出或选错任务 | 先在项目目录交互跑通，确认已生成 `config/maa_pi_config.json` |
| 窗口点不到 | 检查 `window_regex` / 控制器类型；Win32 可用 Seize 鼠标键盘 |
| 日志狂刷 `Window is no longer valid` / screencap failed | 目标窗已关或 HWND 重建；预览会自动断开。确认窗口仍开 → 刷新选窗 → 再连接；高级里优先用 `Background`/`PrintWindow`，少用 `FramePool` |
| 外部 exe 路径失效 | 在「脚本 / 导入」里改 path/workdir 后保存 |
| `start.bat` 失败 | 看 `logs\start_errors.log`；再跑 `python tools\doctor.py` |

## 10. 推荐上手顺序

1. 在仓库根执行：`pip install -r requirements.txt`（或直接 `start.bat`，缺依赖会装）
2. `python tools\doctor.py` 应显示 READY；缺 `maafw` 时 `start.bat` 会调 `setup_maafw.bat`
3. 需要 OCR 练手再：`tools\setup_ocr.bat`
4. `start.bat` → 脚本库对 maafw 项点「编辑」→ ② 录制/连控 →「刷新」选窗口 → 实时截图
5. `tools\open_click_lab.bat`，用记事本跑通「OCR 点确认」
6. 复制 click_lab 做真实游戏项目，导入脚本库，再串队列
